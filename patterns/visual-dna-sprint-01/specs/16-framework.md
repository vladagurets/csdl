# 16 Framework

## Problem

Organize a small set of mutually necessary concepts into one reusable mental model.

## Allowed scenarios

Operating model, assessment lens, teaching framework, or four–six named dimensions.

## Semantic components

The framework title is the `Anchor`; equal concept `Node`s form one `Cluster`; one `Signal` identifies the compounding concept.

## Assembly order

1. Name the framework.
2. Place equal concept Nodes.
3. Relate them as one Cluster without implying false sequence.
4. Select one concept only when the content needs it.

## Expression levels

Levels A and B are allowed. B is canonical because the relationship among four concepts is the teaching object. C is excluded.

## Typography and spacing

Use equal Node typography, open alignment instead of cards, 96 px margins, and `space.5–space.7` between concepts.

## Signal constraints

Coral marks `LEARNING` as retained value and occupies no more than 8%.

## Canonical content

`4 ОПОРИ НАДІЙНОЇ РОБОТИ`: `CONTEXT`, `ACTION`, `EVIDENCE`, `LEARNING`.

## Hard exclusions

No generic four-card dashboard, invented acronym, false chronology, decorative container, or unequal pillar importance.

## Prompt DSL contract

`prompts/16-framework.yaml` defines one open four-node mental model with a single selected concept.

## Acceptance criteria

All four concepts read as mutually necessary; exact labels; no dashboard UI; one coherent CSDL sentence.

## Canonical evidence

One new canonical example selected from three built-in GPT Image 2 candidates.
