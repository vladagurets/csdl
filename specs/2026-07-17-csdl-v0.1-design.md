## 1. Purpose / Мета

CSDL перетворює складні концепти на зрозумілі, запам’ятовувані та придатні до поширення візуальні пояснення.

Це **design language**, а не колекція фіксованих шаблонів. Людина та генеративна модель мають складати композиції з однакових семантичних компонентів, дотримуючись явних правил.

### Primary outcomes / Основні результати

Після перегляду читач має:

1. зрозуміти головну думку за кілька секунд;
2. сформувати просту ментальну модель;
3. запам’ятати один сильний візуальний образ;
4. мати бажання зберегти або поширити матеріал.

### Success criteria / Критерії успіху

- зміст читається на телефоні без збільшення;
- композиція виглядає незвично, але не ускладнює розуміння;
- серія впізнається без логотипа;
- геометрія пояснює структуру, а не прикрашає фон;
- стилістика однаково працює українською та англійською;
- система відтворюється через GPT Image 2 за допомогою reference-first workflow і Prompt DSL.

## 2. Audience and use cases / Аудиторія та сценарії

### Audience / Аудиторія

Читачі Telegram-каналу, які цікавляться:

- AI та agentic development;
- розробкою програмного забезпечення;
- інженерними практиками;
- економікою та системним мисленням.

### Typical materials / Типові матеріали

- одна пояснювальна картка;
- серія з 5–9 карток;
- порівняння підходів або інструментів;
- процес, цикл, pipeline або architecture map;
- одна головна цифра чи 5–10 показників;
- 16:9 адаптація для презентації.

### Content priority / Пріоритет контенту

1. концепції та тези;
2. порівняння;
3. схеми й процеси;
4. числа та компактні набори даних;
5. таблиці та складні графіки — у спеціальному Analytical Mode.

## 3. Historical interpretation / Інтерпретація «Двох квадратів»

CSDL бере з книги Еля Лисицького **метод**, а не історичну оболонку.

### Adopted principles / Запозичені принципи

- **Active negative space.** На сторінках 3, 4 і 10 невелика кількість елементів отримує вагу завдяки великим порожнім полям.
- **Geometry as narrative.** На сторінках 4–9 форми поводяться як сили, об’єкти й події: входять у поле, стикаються, руйнують і перебудовують структуру.
- **Asymmetry with control.** Об’єкти зміщені від центру, але ієрархія залишається однозначною.
- **Semantic color.** Червоний працює як активна дія та зміна, чорний — як маса або опір, білий — як поле.
- **Rhythm across a sequence.** Тихі сторінки чергуються з кульмінаційними; не кожна сторінка є плакатом.
- **Typography as form.** Короткий текст може змінювати масштаб і напрямок, але основна інформація не повинна втрачати читабельність.

### Explicit exclusions / Свідомо виключаємо

- радянську та революційну символіку;
- агітаційні гасла;
- імітацію плакатів 1920-х;
- псевдоісторичні шрифти;
- постійний червоно-чорний клин як декоративний штамп;
- фактуру «старого друку» на кожній сторінці;
- політичні або пропагандистські асоціації.

## 4. Core principles / Основні принципи

### 4.1 Meaning before decoration

Кожен елемент має показувати структуру, статус, напрямок, зв’язок або акцент. Елемент без функції видаляється.

### 4.2 One visual idea per screen

Один екран пояснює одну тезу, одне порівняння, один процес або один набір даних.

### 4.3 Space is content

Порожній простір захищає ієрархію й надає семантичним формам ваги.

### 4.4 Geometry explains

Форми є іменниками, діями та зв’язками. Вони не повинні бути нейтральним декором.

### 4.5 Hierarchy before beauty

Порядок читання має бути очевидним на телефоні до того, як оцінюється естетика.

### 4.6 One idea, one signal

На сторінці є один домінантний акцентний колір і один домінантний маршрут погляду.

### 4.7 Contrast creates memory

Спочатку використовуються масштаб, позиція, тон і ізоляція. Додатковий колір або деталь — лише після цього.

## 5. Expression system / Система рівнів виразності

### Level A — Quiet

**Default / Стандарт:** 60–70% усіх сторінок.

- 60–75% вільного простору;
- один домінантний об’єкт;
- один акцентний колір;
- до двох допоміжних елементів;
- відсутність декоративної рамки;
- відсутність декоративних координатних ліній;
- максимум три типографічні рівні;
- переважно горизонтальна або вертикальна структура;
- діагональ лише як один невеликий функціональний Vector.

### Level B — Constructive

**Use / Використання:** 20–30% сторінок.

- 45–65% вільного простору;
- одна велика семантична форма або один активний Vector;
- два–чотири інформаційні вузли;
- контрольована асиметрія;
- помірне відчуття руху;
- другий службовий колір лише за семантичної потреби;
- один чіткий центр тяжіння.

### Level C — Signal

**Use / Використання:** 5–10% сторінок.

- обкладинка, розділювач, кульмінація або фінальна share card;
- велика площина чи зіткнення форм;
- плакатний контраст дозволений;
- текст коротший, ніж на Level A/B;
- все одно лише одна головна думка та один маршрут читання.

### Default rhythm / Типовий ритм серії

```text
A → A → B → A → B → A → C
```

Заборонено будувати серію з кількох Level C поспіль.

## 6. Canonical canvas / Канонічний формат

### 6.1 Master canvas

```yaml
ratio: 4:5
width: 1080
height: 1350
orientation: portrait
role: canonical social master
```

Це головний artboard для Telegram та соціальної інфографіки. Усі первинні композиційні рішення ухвалюються тут.

### 6.2 Safe area

- зовнішній горизонтальний margin: **72 px**;
- зовнішній вертикальний margin: **72 px**;
- критичний текст не ближче **64 px** до краю;
- службовий номер або серійний маркер може входити в outer band, але не є обов’язковим;
- footer не повторюється на кожній картці.

### 6.3 Grid

```yaml
columns: 12
column_width: 56px
gutter: 24px
outer_margin: 72px
baseline_unit: 8px
```

Перевірка ширини:

```text
72 + (12 × 56) + (11 × 24) + 72 = 1080
```

### 6.4 Spacing tokens

```text
space.1  = 8 px
space.2  = 16 px
space.3  = 24 px
space.4  = 32 px
space.5  = 48 px
space.6  = 64 px
space.7  = 96 px
space.8  = 128 px
```

Вільний простір між головними зонами переважно використовує `space.6–space.8`. Дрібні інтервали всередині компонентів — `space.1–space.4`.

### 6.5 Default reading path

- старт: верхня ліва або верхня центральна зона;
- завершення: нижня права або нижня центральна зона;
- максимум один активний напрямок руху;
- не більше двох напрямків читання навіть на Level C;
- основний текст ніколи не обертається.

### 6.6 16:9 adaptation

```yaml
ratio: 16:9
width: 1920
height: 1080
role: secondary presentation adaptation
columns: 12
outer_margin: 96px
gutter: 24px
```

16:9 версія **перебудовує** ієрархію й відносини компонентів. Заборонені просте обрізання, розтягування або механічне перенесення координат із 4:5.

## 7. Density rules / Правила щільності

### Standard card / Звичайна картка

- одна головна теза;
- один головний візуальний механізм;
- до трьох допоміжних елементів;
- орієнтовно до 30–40 слів пояснювального тексту;
- один акцент займає приблизно 5–12% площі;
- один очевидний entry point;
- один очевидний exit point.

### Hard constraint / Жорстке обмеження

Картка не може бути щільною одночасно в трьох вимірах:

1. текст;
2. геометрія;
3. колір.

Якщо один вимір стає щільнішим, два інші спрощуються.

### Analytical Mode

Для таблиць, heatmap, dashboard і багатосерійних графіків:

- декоративна геометрія майже вимикається;
- фонова площина відсутня або займає не більше 5%;
- точність шкал важливіша за фірмову асиметрію;
- прямі підписи кращі за легенду;
- одна серія виділяється, решта нейтралізується;
- колір не є єдиним носієм значення.

## 8. Typography system / Типографічна система

### 8.1 Role 1 — Display / Modular Technical

**Purpose:** обкладинки, короткі заголовки, ключові терміни, великі числа.

**Visual traits:**

- квадратні або інженерні пропорції;
- чіткі зрізи та модульний ритм;
- технічний характер без sci-fi novelty;
- компактний spacing;
- сильні цифри й символи;
- повна українська та англійська підтримка;
- жодної історичної імітації 1920-х.

**Pilot reference implementation:** `Tektur` Semibold/Bold, з контрольованою width-варіацією.

### 8.2 Role 2 — Reading / Neutral Sans

**Purpose:** пояснення, підписи, короткі абзаци, двомовні терміни.

**Traits:** висока читабельність, відкриті форми, нейтральний ритм, якісні цифри.

**Pilot reference implementation:** `IBM Plex Sans` Regular/Medium.

### 8.3 Role 3 — Code / Monospace

**Purpose:** код, команди, формули, Prompt DSL, system sequences.

**Pilot reference implementation:** `IBM Plex Mono` Regular/Medium.

### 8.4 Type scale for 1080 × 1350

| Token | Size | Line height | Use |
|---|---:|---:|---|
| `display.hero` | 104–144 px | 0.88–0.95 | 1–5 words, 2–4 lines |
| `display.h1` | 72–96 px | 0.92–1.00 | основний заголовок |
| `display.h2` | 44–56 px | 1.00–1.08 | секція або ключовий підзаголовок |
| `body.lead` | 34–40 px | 1.20–1.32 | коротка теза |
| `body.base` | 28–34 px | 1.30–1.45 | пояснення |
| `label` | 22–26 px | 1.10–1.25 | вузли, осі, службові підписи |
| `code` | 26–30 px | 1.20–1.35 | команди, формули, DSL |
| `meta` | 18–22 px | 1.10–1.25 | номер, джерело, маркер серії |

### 8.5 Typography limits

Allowed:

- обертання короткого label;
- фрагментація одного display-слова;
- великий окремий символ або число;
- часткове перекриття display-гліфа геометрією на Level B/C;
- зміна width/weight для смислового контрасту.

Not allowed:

- обертання body copy;
- більше двох напрямків читання;
- перекриття критичного тексту;
- більше одного типографічного трюку на картці;
- одночасне використання outline, shadow, rotation, fragmentation і кількох кольорів;
- довгі абзаци у display-шрифті.

### 8.6 AI rendering note

Назви шрифтів є **reference targets**, а не гарантією точного відтворення гліфів. Prompt має описувати роль і форму типографіки; точність тексту перевіряється після кожної генерації. Варіант із помилковим українським або англійським текстом не входить до Visual DNA Gallery.

### 9.3 Color rules

- нормальна картка: paper + graphite + **one signal**;
- службові кольори не повинні з’являтися разом без змістовної причини;
- body text завжди графітний або світлий нейтральний;
- пастельність створюється зниженням chroma, а не надмірним освітленням;
- колір підсилює значення, але не замінює форму, позицію або підпис;
- на Level A акцент займає 3–8% площі;
- на Level B — 5–12%;
- на Level C — 12–25%, але однією домінантною площиною.

## 10. Visual grammar / Візуальна граматика

### 10.1 Nouns / Іменники

| Component | Meaning / Значення |
|---|---|
| `Anchor` | головна теза або центральний концепт |
| `Signal` | елемент, що потребує негайної уваги |
| `Frame` | scope або аналітична межа |
| `Field` | контекст чи середовище |
| `Cluster` | група пов’язаних концептів або доказів |
| `Pulse` | одна ключова цифра чи показник |
| `Node` | окремий етап, актор або data point |

### 10.2 Verbs / Дії

```text
Split · Merge · Flow · Expand · Collapse · Rotate
Intersect · Focus · Highlight · Repeat · Accumulate · Transform
```

### 10.3 Relations / Зв’язки

```text
inside · outside · overlap · parallel · connected · detached
nested · mirrored · balanced · tension · sequence · hierarchy
```

### 10.4 Structural components / Структурні компоненти

| Component | Meaning / Значення |
|---|---|
| `Vector` | напрямок, дія або трансформація |
| `Collision` | конфлікт, порівняння або точка синтезу |
| `Bridge` | зв’язок між віддаленими концептами |
| `Loop` | циклічний процес |
| `Axis` | безперервне порівняння або прогресія |
| `Divider` | поділ областей чи позицій |
| `Container` | функціональна група; не декоративна card shell |

### 10.5 Example composition sentence

```text
One Anchor inside one open Field,
connected to two Clusters by one Vector,
balanced by negative space,
with one primary Signal.
```

## 11. Calibrated recipes / Контрольні рецепти

### 11.1 Recipe `001 Hero`

**Purpose:** одна теза, яку треба зрозуміти й запам’ятати.

#### Level A

```yaml
components:
  Anchor: 1
  Signal: 1
  supporting_text: 1
  decorative_geometry: 0
```

- заголовок займає 4–7 колонок;
- одна проста форма або кольорова площина;
- до двох рядків пояснення;
- 65–75% вільного простору.

#### Level B

- додається один Vector або одна взаємодія двох форм;
- до трьох допоміжних елементів;
- асиметрія підсилює тезу.

#### Level C

- велика Signal-plane;
- дуже короткий текст;
- використовується як обкладинка або кульмінація.

### 11.2 Recipe `005 Comparison`

**Purpose:** показати дві позиції, системи або моделі.

#### Level A

```yaml
components:
  Anchor: 2
  Divider: 1
  criteria_per_side: 3
  Signal: 1
```

- два відкриті поля;
- максимум три критерії на сторону;
- без вибуху, уламків або декоративного Collision;
- різниця читається через структуру й підписи.

#### Level B

- центральний `Collision` або `VS` стає функціональним вузлом;
- кожна сторона має один семантичний колір;
- зберігається велике повітряне поле.

#### Level C

- сильна тональна асиметрія;
- одна сторона може бути темною площиною;
- використовується рідко й лише для принципового конфлікту.

### 11.3 Recipe `013 Loop`

**Purpose:** показати повторюваний процес із 3–5 стадій.

#### Level A

```yaml
components:
  Loop: 1
  Nodes: 4
  Signal: 1
  center_copy: 0
```

- тонкі connectors;
- один активний node;
- без кольорової плитки за кожним етапом.

#### Level B

- 3–4 nodes можуть мати семантичне кодування;
- коротка теза в центрі;
- один node виділяється як поточний.

#### Level C

- велика кругова Field або Signal-plane;
- текст у центрі короткий;
- застосовується для кульмінаційної ментальної моделі.

## 12. Prompt DSL — minimal schema / Мінімальна схема

```yaml
language: CSDL
version: 0.1

canvas:
  ratio: 4:5
  size: 1080x1350
  safe_margin: 72

mode:
  expression: A        # A | B | C
  density: low         # low | medium | analytical
  motion: low          # none | low | medium
  contrast: high

recipe: Hero            # Hero | Comparison | Loop | ...

composition:
  anchor: 1
  signal: 1
  clusters: 0
  vectors: 0
  reading_path: top-left_to_bottom-right
  negative_space: 70%

typography:
  display: modular_technical
  body: neutral_sans
  code: technical_mono
  languages: [uk, en]

palette:
  mode: light
  primary_signal: coral
  service_color: none

constraints:
  one_main_idea: true
  one_visual_mechanism: true
  max_supporting_elements: 3
  no_decorative_footer: true
  no_political_symbols: true
  no_retro_propaganda: true
  accurate_text_required: true
```

### Prompt rule

Prompt повинен описувати:

1. зміст;
2. recipe;
3. expression level;
4. component grammar;
5. reading path;
6. typography roles;
7. palette semantics;
8. hard exclusions.

Фраза «зроби красиву інфографіку» не є допустимою специфікацією.

## 13. Reference-first generation workflow / Генеративний процес

```text
Content brief
→ Information hierarchy
→ CSDL recipe
→ Prompt DSL
→ Approved visual reference
→ GPT Image 2 generation
→ Text and hierarchy review
→ Targeted regeneration/edit
→ Canonical reference or rejected draft
```

### Canonical reference requirements

Зображення входить до Visual DNA Gallery лише якщо:

- текст точний;
- ієрархія зрозуміла за 2–3 секунди;
- воно відповідає заявленому Level A/B/C;
- акцент семантичний;
- немає випадкових ліній, рамок або псевдоінтерфейсних деталей;
- mobile preview читається без zoom;
- композиція може бути описана CSDL-реченням.

## 14. Quality rubric / Шкала оцінювання

Кожна картка оцінюється від 1 до 5.

| Criterion | 1 | 3 | 5 |
|---|---|---|---|
| `Clarity` | думка неочевидна | зрозуміла після читання | зрозуміла за 2–3 секунди |
| `Mobile readability` | потрібен zoom | читається з напругою | читається природно |
| `Memorability` | немає образу | один помірний акцент | один сильний образ |
| `CSDL identity` | generic design | частково впізнавана | впізнавана без логотипа |
| `Restraint` | перевантаження | кілька зайвих деталей | нічого не можна прибрати |
| `Text fidelity` | помилки | дрібні похибки | publish-ready text |
| `Semantic integrity` | форми випадкові | частково функціональні | кожна форма має роль |

### Acceptance threshold

- жоден критерій нижче `4`;
- середній бал не нижче `4.4`;
- `Clarity`, `Mobile readability` і `Text fidelity` мають бути `5` для публікації.

## 15. Pilot 01 / Пілотна серія

### Topic

**Agentic Discipline: Superpowers vs Compound Engineering**

### Seven-card sequence

1. **Hook — Level A:** системи перемагають ізольовані зусилля з часом.
2. **Problem — Level A:** чому ad-hoc agent work стає непередбачуваною.
3. **Model — Level B:** standards, checks, boundaries, memory.
4. **Comparison — Level A/B:** різні механізми дисципліни Superpowers і Compound Engineering.
5. **Synthesis — Level B:** auto-discipline loop для agentic development.
6. **Takeaway — Level A:** компактна operational mental model.
7. **Share card — Level C:** одна запам’ятовувана формула.

### Pilot deliverables

- 7 окремих 4:5 карток у 1080 × 1350;

- 3 ключові 16:9 адаптації;
- 1 Prompt DSL файл;
- 1 evaluation sheet за Quality Rubric;

## 17. Spec self-review / Самоперевірка

- Placeholder scan: відсутні `TBD`, `TODO` і невизначені обов’язкові рішення.
- Internal consistency: 4:5 є канонічним форматом у всіх розділах; 16:9 визначений як адаптація.
- Scope check: документ описує Foundation v0.1 та Pilot 01, а не повну майбутню систему.
- Ambiguity check: рівні A/B/C, grid, margins, density, typography roles, colors і acceptance criteria визначені явно.
- Non-goal check: специфікація не намагається передчасно зафіксувати повний Cookbook або всі chart patterns.
